How to validate safely

  1. Confirm authorization first. Test only assets you own or have written permission to assess, within an agreed scope and time window.
  2. Start with inventory, not probes. Check installed versions through the asset owner, package manager, management console or SBOM, and compare them with the vendor’s fixed versions.
  3. Prefer passive and authenticated checks. Version and configuration checks run as an authorized user are more accurate and less disruptive than network probes.
  4. Treat banner or version matches as “suspected”. Backported patches and mitigations often make a version string look vulnerable when it isn’t.
  5. Use reviewed detection checks only where approved. Templates tagged intrusive or using out-of-band callbacks need change approval and a maintenance window.
  6. Confirm with a human before calling it exploitable. Record the method, evidence, time and who confirmed it.
  7. Re-check after remediation. Verify the fixed version or mitigation is in place, using the same method that found the issue.
